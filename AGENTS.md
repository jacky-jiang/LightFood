## Architecture

Use SwiftUI + MVVM.

Allowed dependency direction:

App → Features → Core / Shared

Forbidden dependencies:

- Views -> Networking
- Views -> Storage
- Core -> Features
- Shared -> Features

## Swift Rules

- Use async/await for asynchronous work.
- Avoid force unwrap unless explicitly justified.
- Prefer value types for models.
- Prefer final classes for reference types that are not designed for subclassing.
- Use clear access control.
- Keep functions small and focused.

## SwiftUI Rules

- Views should be declarative and lightweight.
- Do not put networking code directly inside SwiftUI Views.
- ViewModels own view state and user interaction logic.
- Use @State only for local UI state.
- Use @StateObject for long-lived ObservableObject view models.
- Extract complex views into smaller subviews.

## Testing Rules

- ViewModels with branching logic must have unit tests.
- Services must be testable through protocols.
- Do not rely on live network calls in unit tests.

## CI Rules

- Use xcodebuild for CI build and test.
- Do not require code signing for simulator tests.
- Keep CI workflow minimal and reproducible.
